# 技术限制

HotkeyLens 的目标是可靠地展示“有证据支持的信息”，而不是制造一个看似完整的快捷键数据库。以下限制来自 Windows 平台、应用实现差异和当前项目的实现范围。

## 1. Windows 没有全局快捷键枚举 API

Windows 没有公开接口可以列出其他进程通过 `RegisterHotKey` 注册的全部全局快捷键。

- `RegisterHotKey` 用于当前进程注册热键，没有配套的“枚举所有进程”接口。
- `UnregisterHotKey` 只能释放本进程注册的 ID。
- `WH_KEYBOARD_LL` 是实时键盘事件监听机制，不是静态扫描机制；HotkeyLens 不使用它。
- 内核驱动或带保护的服务注册的热键更无法通过普通用户态程序读取。

因此 HotkeyLens 不能回答“这台电脑上所有全局热键的完整列表”。它能回答的是：在可读取的快捷方式、配置、UI 和内置文档中，有哪些有证据的绑定。

## 2. 快捷方式热键的边界

`.lnk` 文件中的 `HotKey` 字段表示快捷方式配置的全局热键。读取它不需要启动目标程序，但存在以下限制：

- 只能发现开始菜单、公共开始菜单、用户桌面和公共桌面上存在的快捷方式；
- 需要 Windows Script Host 能解析快捷方式目标；被策略禁用或目标损坏时无法映射应用；
- 快捷方式配置了热键，不代表注册一定成功；目标程序未运行、热键被其他程序占用或系统策略阻止时可能注册失败；
- 界面将其来源标为“实际配置/快捷方式热键”，并结合理由说明它不是对内核注册状态的实时验证。

## 3. UI Automation 的边界

UI Automation 只暴露应用主动提供的可访问性信息。它看不到不存在于 UI 树中的快捷键，也无法强制应用公开隐藏菜单。

- 只能扫描当前已经打开的窗口；HotkeyLens 不会启动应用；
- 不展开菜单，因此只读取当前 UI 树中已存在的菜单项；
- 部分应用菜单是自绘或未正确设置 `AcceleratorKey`；
- 以管理员权限运行的应用、受保护窗口或安全桌面可能无法访问；
- UI Automation 调用可能被目标应用阻塞，适配器设置超时并记录诊断，但底层调用可能在线程池中自然结束；
- 运行时观察不代表默认配置，也不代表用户偏好。

## 4. 官方文档的边界

内置官方目录只包含经过核实的少量应用，并附带来源 URL：

- 官方文档通常描述默认键位，不反映用户当前自定义；
- 文档可能对应某一版本，软件升级后键位可能变化；
- 不同平台（Windows/macOS/Linux）的键位可能不同，目录只收录 Windows 版本；
- 不是所有官方快捷键都能结构化表示，例如双击 Shift 这类手势未纳入；
- 没有可靠来源的软件不会加入目录。

## 5. 配置文件解析的边界

当前支持 VS Code、Windows Terminal、JetBrains、Notepad++，以及 Chrome/Edge 的扩展快捷键（`Preferences` 中的 `extensions.commands`）和 Snipaste 的 `config.ini`：

- 不同软件版本的 JSON/XML/INI schema 可能变化，Chrome 新旧两代 `extensions.commands` 结构都已兼容，但仍可能有未覆盖的变体；
- 用户配置可能使用变量、条件表达式、上下文表达式或继承机制，无法完全还原实际生效状态；
- 只读取已知路径下存在的用户配置（含浏览器 `Default` / `Profile N` 目录），不读取私有数据库或内存；
- 浏览器扩展快捷键以浏览器写入 `Preferences` 的键位为准；扩展被停用、卸载或尚未同步时，记录可能残留或缺失；
- 扩展名称优先读取 `extensions.settings`，再尝试扩展目录里的 `manifest.json`；本地化占位名（`__MSG_...__`）无法解析时只显示扩展 ID 前缀；
- Snipaste 配置不记录作用域字段，HotkeyLens 按 Snipaste 全局热键的常规行为标为全局，并在理由中说明该推断；
- 解析失败会生成诊断，并跳过无法可靠解析的条目，不会用默认值冒充用户配置；
- 没有覆盖的软件显示“无法自动读取”，而不是“没有快捷键”。

## 6. 冲突分析的边界

冲突分析是基于当前快照的静态证据推断，不是操作系统级别的注册验证。

- 两个应用使用相同按键，不一定发生冲突；
- 普通应用级绑定归为“正常重复”，不计入冲突；
- 同一应用只有在上下文可能重叠时才检查同键不同功能；
- 至少两个 `.lnk` 全局注册证据，才把跨应用结果标为“确认冲突”；
- 作用范围、上下文、注册证据缺失时归类为潜在冲突或未知；
- 扫描开始时读取一次进程表，仅用于判断“当前是否同时运行”，不做后台监听：
  - 两个（或多个）应用声明同一全局热键且**都在运行**时，标为“潜在冲突 · 全局热键竞争”（中等显著度），提示可能被先启动的软件抢占；
  - 至少一个未检测到运行时降为低显著度，并在摘要中注明“仅在同时开启时才可能竞争”；
  - 运行状态采集失败或不可见时标为“运行状态未知”，不臆断为未运行；
- 进程表可能因权限、会话隔离或安全软件限制而不完整：当可读进程名少于 25 个时视为不完整，未命中的应用一律标为“状态未知”，而不是“未运行”；
- 除进程表外，还会读取可见顶层窗口的所属进程作为兜底；微信、网易云音乐等保护了主进程的应用即使进程枚举被过滤，也能通过窗口恢复识别；
- 即使双方都未运行、运行状态未知，同一全局热键仍会作为低显著度潜在冲突保留，避免用户下次开启时毫无提示；
- 多段按键序列不参与冲突分析；
- 已知的全局注册结果可能因启动顺序、权限和系统策略而变化；
- 结果用于提示和排查，不构成“已确认冲突”的系统事实。

## 7. 快捷键管理的边界

- 只提供打开配置文件/安装目录、切换并激活已运行应用窗口、复检冲突的能力，不自动修改第三方配置文件；
- “切换到该应用”仅在扫描时观察到该应用运行时可用；点击后恢复最小化窗口并尝试置前，Windows 因权限或前台锁定拒绝时会给出提示而不是崩溃；
- “打开所在目录 / 配置文件”只对扫描时已验证存在的路径可用；文件被移动或卸载后会提示不可用；
- 打开资源管理器时会等待约 0.9 秒并检查退出码：`explorer.exe` 正常交接给现有 shell 时通常返回 1，只有负数（NTSTATUS，例如 `0xC0000142`）才判定为启动失败，并显示错误码与目标路径供手动前往，不误报“已定位”；若进程在检查窗口内仍在运行，则按成功处理；
- “复检此冲突”会重新执行一次只读扫描，并对比同一按键组合是否仍有冲突，不会替用户改动任何设置；
- 不承诺支持通过私有 API 禁用或重绑快捷键；
- 部分应用的设置只能在其界面中修改，无法可靠自动化；
- 即使支持编辑，也需要版本适配、自动备份和恢复验证，当前未实现。

## 8. 应用发现的边界

- 只读取注册表卸载项、`App Paths`、开始菜单/桌面快捷方式、内置 Shell，以及微信、QQ、网易云音乐、QQ音乐、Snipaste、ShareX 的常见安装位置（仅在文件真实存在时收录）；
- 便携版、绿色版、Microsoft Store 应用、驱动组件不一定被发现；
- 某些安装器会留下无有效目标的卸载项，可能被过滤或显示为低信息应用；
- 应用版本取决于文件版本信息，部分程序没有版本资源；
- 同名应用会结合路径和发布者区分，但无法保证所有第三方软件都提供唯一元数据。

扫描状态中的“无法自动读取”只说明没有可用的扫描来源，不代表应用没有快捷键。

## 9. 保存与运行环境

- 默认数据目录是 `%LOCALAPPDATA%\HotkeyLens`；
- 保存使用唯一临时文件、`FileShare.None`、Flush、优先 `File.Replace` 并保留 `.bak`；失败时保留旧快照，主文件损坏时回退备份；
- 当前开发机器上，火绒的主机防御对新建、未签名的 .NET 进程访问用户目录返回 `ACCESS_DENIED`；PowerShell 等受信任进程访问同一路径正常。这不是文件 ACL 或程序并发问题；
- 同一环境下，火绒也可能过滤未签名开发版的进程枚举：实测只能读到 10～17 个进程名，而受信任的 PowerShell 可读到 303 个。HotkeyLens 会把这种偏少的进程表判为不完整，未命中的应用显示“状态未知”；微信、网易云音乐等可通过可见窗口兜底识别。签名发布版或把程序加入信任列表后通常能恢复完整枚举；
- 在此类安全软件环境下，需要由用户将 HotkeyLens 加入信任/应用放行列表，或使用受控的 `HOTKEYLENS_DATA_DIR` 测试目录；
- HotkeyLens 不会尝试绕过安全软件，也不会用改名、关闭保存或伪造成功来规避问题。

## 10. 主题与界面

- 支持浅色、深色和跟随系统三种选择；
- 主题切换立即应用到所有已实现控件，并自动保存；
- “跟随系统”在启动/选择时读取 Windows 应用主题；运行期间 Windows 系统主题改变后，需要重新选择或重启应用才会重新解析；
- 自定义窗口边框和标题栏在 Windows 10/11 的高 DPI 缩放下依赖 WPF 的 DPI 处理；已在 120 DPI 环境验证，其他缩放比例建议复测；
- 仅验证当前 Windows 11 构建（10.0.26300）；Windows 10 22H2 未在当前机器实测。

## 11. 不在项目范围内

- 后台常驻、开机启动、托盘、持续键盘监听；
- 读取/修改其他进程内存；
- 绕过安全软件或系统权限；
- 自动修改未明确支持的第三方配置；
- 伪造快捷键或把推测标成已验证。

## 12. 当前内置目录的覆盖范围

内置官方目录覆盖 16 个应用：

- Microsoft Word
- Microsoft Excel
- Microsoft PowerPoint
- Google Chrome
- Microsoft Edge
- Adobe Photoshop
- Visual Studio Code / Insiders
- Windows Terminal
- JetBrains IDEs（IDEA、PyCharm、WebStorm、CLion、GoLand、Rider、PhpStorm、RubyMine、DataGrip、Android Studio 等进程）
- Notepad++
- Windows Shell（explorer.exe）
- 网易云音乐
- QQ音乐
- 微信（WeChat.exe / Weixin.exe）
- QQ
- Snipaste

Word、Excel、PowerPoint、Chrome、Edge、Photoshop 以及新增的音乐/社交/截图软件，在内置目录里只提供“官方默认规则”，不冒充用户自定义配置；微信、QQ、网易云音乐的本地配置为私有格式，本版本仍不读取。

微信、QQ、网易云音乐、QQ音乐、Snipaste、ShareX 的常见安装位置会被只读探测（文件存在才收录），因此即使没有注册表卸载项也能出现在应用列表里；ShareX 默认不启用全局热键，界面只提供“打开设置位置”的指引，不虚构默认键位。
